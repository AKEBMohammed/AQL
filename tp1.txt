Tests Unitaires TP3
Tests d’intégration – partie 1
Objectifs
Ce TP vous guidera à travers les tests d'intégration sur Java en utilisant différents
scénarios de complexité croissante. Nous explorerons les tests d'interaction entre les
modules, les bases de données et les API. Vous allez apprendre dans cette première
partie de ce TP:
 Comprendre les concepts des tests d'intégration en Java.
 Pratiquer l'écriture de tests d'intégration en utilisant JUnit.
 Implémenter des mocks pour les dépendances pendant les tests.
Prérequis
Pour réaliser cette ce TP, vous devez avoir:
 Une version de Java 8 ou supérieure
 Un IDE Intellij IDEA
 Une connexion internet
 Les premiers manuels de TP sur les tests unitaires avec JUnit 5
Pour ce TP, il est question d’implémenter les classes nécessaires pour chaque exercice
et d’écrire des tests d’intégration pour chaque cas. Pusher vos implémentations ainsi
que vos tests par vos comptes Github. N’oublier pas de pusher vos réponses aux
questions dans un fichier README sur votre repository.
Exercice1 : Interaction Simple entre Modules
Scénario :
Une classe UserService récupère les données d'un utilisateur à partir d'une classe
UserRepository .
Tâches :
1. Créer une classe UserService avec une méthode getUserById(long id) qui
récupère un objet utilisateur du UserRepository .
2. Créer une interface UserRepository avec une méthode findUserById(long
id).
3. Écrire un test JUnit pour UserService.getUserById(long id) . Utilisez un objet
mock pour UserRepository afin de simuler la récupération de l'utilisateur.
2
4. Dans le test, vérifiez que la méthode findUserById sur l'objet mock est appelée
avec le bon argument lorsque UserService.getUserById est appelée.
Exercice 2 : Interaction avec une Base de Données avec des Mocks
Scénario :
Une classe OrderController interagit avec un OrderService pour créer une
commande. L'OrderService enregistre les détails de la commande dans une base de
données à l'aide d'une classe OrderDao (Dao : Data access object).
Tâches :
1. Créer une classe OrderController avec une méthode createOrder(Order
order) qui appelle OrderService.createOrder(order).
2. Créer une classe OrderService avec une méthode createOrder(Order order)
qui appelle OrderDao.saveOrder(order).
3. Créer une interface OrderDao avec une méthode saveOrder(Order order).
4. Écrire un test JUnit pour OrderController.createOrder(Order order). Utilisez
des mocks pour OrderService et OrderDao .
5. Dans le test, vérifiez que OrderService.createOrder est appelé avec le bon
argument et que OrderDao.saveOrder est appelé avec l'objet de commande
créé.
Exercice 3 : Intégration d'API avec Mocking
Scénario :
Un ProductService récupère des informations sur un produit à partir d'une API externe
à l'aide d'un ProductApiClient .
Tâches :
1. Créer une classe ProductService avec une méthode getProduct(String
productId) qui récupère les détails du produit en appelant
ProductApiClient.getProduct(productId ).
2. Créer une interface ProductApiClient avec une méthode getProduct(String
productId) qui simule un appel d'API (vous pouvez utiliser une réponse
prédéfinie ou lever une exception).
3. Écrire un test JUnit pour ProductService.getProduct(String productId) .
Utilisez un objet mock pour ProductApiClient.
4. Dans le test, vérifiez que ProductApiClient.getProduct est appelé avec le bon
argument. Tester également ces différents scénarios : récupération réussie,
format de donnée incompatible, échecs d'appel d'API.
